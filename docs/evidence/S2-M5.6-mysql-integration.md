## Scope

This evidence records the implementation and local verification for wiring validation to the M1 label/allergen contracts, M2 validation persistence, M4 authorization, and the audit seam.

## Existing implementation found

- SCRUM-28 already provided JDBC repositories for `RuleSetVersion`, `ValidationRun`, and `ValidationResult`.

- V3 already seeded `ruleset_us_falcpa_demo_v1` as `ACTIVE`, v2 as `DRAFT`, the authorized label officer, and `LABEL.VALIDATE`.

## Files changed

- Added validation application service, HTTP controller, error mapping, and response/request DTOs.
- Added M1 label snapshot port/DTO and owner-side JDBC adapter.
- Added allergen facts port/DTO and owner-side JDBC adapter.
- Added M4 request authorization port and adapter using the existing identity/RBAC services.
- Added the audit application port and real validation audit persistence through `AuditApplicationService`.
- Added HTTP-to-MySQL integration coverage and ArchUnit rules.
- Updated the OpenAPI description to reflect the implemented boundary.

## Integration flow

`HTTP → ValidationController → ValidationApplicationService → LabelSnapshotPort / AllergenFactsPort / AuthorizationPort / RuleSetVersionRepository → owner-side JDBC adapters → MySQL → validation_run + validation_result + audit_event`

The validation application layer does not import `CatalogStore`, `JdbcIdentityRepository`, foreign JDBC adapters, or execute SQL. IDs remain server-assigned; cross-module records use explicit camelCase Java components; persisted timestamps are UTC.
